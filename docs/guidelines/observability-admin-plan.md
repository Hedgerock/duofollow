# План облачного мониторинга и админ-панели

## Статус и назначение

Рассматривается будущее расширение для диагностики ошибок сайта и Connector, проверки доступности
публичных страниц и просмотра состояния выпусков. План предусматривает бесплатный облачный тариф
с ограничением объёма событий и отдельную админ-панель.

Сравнение и отписка сейчас выполняются в браузере. Внешняя телеметрия добавляет отдельного получателя
технических данных. Реализация сопровождается ADR с выбором сервиса, составом данных, сроком хранения,
доступом администратора и обновлением публичной политики на поддерживаемых языках.

Окончательный выбор выполняется после прототипа. Проверка тарифа включает приём событий, просмотр,
API чтения, уведомления, экспорт и поведение при исчерпании квоты.
Условия для длительного бесплатного использования фиксируются отдельно от пробного платного периода.

прототип подтверждает доступность конкретных методов на бесплатном тарифе.
Выбор другого сервиса или собственного хранилища рассматривается в том же ADR.
[Сравнение возможностей Sentry](https://sentry.io/pricing/).

## Состав диагностических событий

Планируется ограниченный набор структурированных событий.

| Поле                         | Содержимое                                                                               |
| ---------------------------- | ---------------------------------------------------------------------------------------- |
| Время, уровень и тип события | Ошибка интерфейса, тайм-аут обмена, неверный формат ответа или восстановление соединения |
| Компонент и версия           | Сайт или Connector, версия сборки и окружение                                            |
| Код ошибки и операция        | Проверенный код Connector и обозначение проверки сессии, сравнения или отписки           |
| Маршрут                      | Тип страницы или шаблон маршрута без параметров профиля                                  |
| Длительность                 | Время выполнения операции или диапазон задержки                                          |
| Корреляция                   | Короткоживущий случайный ID операции для сопоставления технических событий               |

Очистка выполняется до отправки и проверяется на приёмной стороне. Передаются только поля принятой схемы.
Сессионные cookie, токены, содержимое запросов и ответов Duolingo, ID аккаунтов, имена, аватары,
списки подписок и поисковые строки исключаются из схемы. Произвольный текст ошибки и URL
заменяются кодом или очищенным шаблоном. Сетевые метаданные, доступные облачному получателю,
учитываются при настройке хранения и описании обработки данных.

Ожидаемые состояния выдачи доступа и выхода из аккаунта получают собственную классификацию.
Повторяющиеся события объединяются. Успешные операции собираются выборочно в пределах заданного бюджета.
Глобальный перехват консоли и запись содержимого пользовательского интерфейса требуют отдельного обоснования.

## Доступность и оповещения

Внешние проверки обращаются к публичной главной и выбранным информационным страницам DuoFollow.
Они фиксируют HTTP-ответ и время загрузки. Работа авторизованной сессии Duolingo проверяется
отдельным пользовательским сценарием.

Оповещение содержит тип инцидента, время, версию и ссылку на защищённую диагностику.
Одинаковые ошибки группируются. Проверка восстановления закрывает инцидент.
Порог и период проверки выбираются по квоте сервиса и результатам прототипа.

## Админ-панель

Первый вариант панели предназначен для просмотра состояния проекта.

- Сводка доступности сайта, текущей версии и последних инцидентов.
- Список технических событий с фильтром по времени, версии, браузеру, компоненту и коду.
- Динамика ошибок и задержек по доступным агрегатам.
- Информация о квоте и сроке хранения, если выбранный сервис предоставляет эти сведения.
- Ссылки на выпуск и подробности инцидента в облачном кабинете.

Область первой версии ограничена технической диагностикой.
Управление аккаунтами Duolingo и выполнение отписок сохраняют существующий пользовательский сценарий.
Дополнительные административные действия получают самостоятельное описание прав и последствий.

Доступ к данным проверяет серверный API или облачный шлюз авторизации.
Секреты чтения сервиса хранятся на серверной стороне. Публичный идентификатор приёмника событий
оценивается отдельно от секретного ключа администратора. Клиентская сборка содержит только разрешённую
публичную конфигурацию. CORS дополняет серверную проверку доступа.

Сайт на GitHub Pages обращается к защищённому API панели. Способ размещения самой панели,
авторизация одного администратора и обработка истёкшей сессии фиксируются в ADR реализации.

## Этапы реализации и проверки

1. Прототип проверяет бесплатный тариф, приём очищенного события, уведомление, API чтения и квоты.
2. Ограниченная интеграция сайта и Connector добавляет схему событий, очистку, группировку и настройку сбора.
   Публичная политика описывает получателя, цели, данные, срок хранения и управление сбором.
3. Внешняя проверка сайта и оповещения проходят контрольный сценарий недоступности и восстановления.
4. Админ-панель подключает авторизацию, просмотр инцидентов и доступные агрегаты.
5. Приёмка проверяет доступ без авторизации, отзыв доступа администратора, очистку данных и исчерпание квоты.
   Недоступность сервиса и переполнение очереди сохраняют работоспособность сравнения и отписки.

Очередь имеет ограничение размера и срока жизни. Повторы используют ограниченное число попыток и задержку.
Перед публичным включением измеряются размер сборки, расход памяти и влияние отправки событий на слабом ПК.
Выбранный сервис, серверный API и фактические условия использования описываются в актуальной архитектуре
и руководстве выпуска вместе с реализацией.

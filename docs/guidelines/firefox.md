# Firefox

## Состояние

Реализованы отдельная сборка WebExtensions, browser-адаптер и канал сайт → content script → core.
Разработчик подтвердил успешную ручную проверку 26 ноября 2026 года в Firefox 161.0 на Windows 11:
подключение, сравнение, возврат из политики, нативная сортировка и управление подсказками с клавиатуры
выполнили ожидаемое поведение; дефектов не обнаружено.
Минимальная версия Firefox Desktop в manifest — 140; ручной результат относится к Firefox 161.0 на Windows 11.
Расширенная матрица совместимости и публичное распространение требуют отдельной приёмки.
Android, приватные и контейнерные профили не входят в подтверждённую поддержку.
[ADR-0017](../decisions/records/0017-firefox-bridge-and-build.md) · [Результаты проверки](../reviews/2026-11-25-firefox.md)

## Установка для разработки

Команды выполняются из корня проекта после npm ci:

```powershell
npm run extension:firefox:build
npm run extension:firefox:lint
npm run extension:firefox:run
```

web-ext run открывает временный профиль установленного Firefox. Альтернатива — страница
about:debugging#/runtime/this-firefox, пункт Load Temporary Add-on и файл extension/dist-firefox/manifest.json.
Такая установка действует до перезапуска Firefox. Управление разрешениями доступно в about:addons.
Сборка разработки разрешает DuoFollow на localhost:5173 и 127.0.0.1:5173.
После временной установки требуется обновление уже открытой страницы сайта.

Сессия Duolingo и сайт DuoFollow находятся в том же обычном профиле Firefox.
Страница доступа открывается через значок расширения или управление доступом на сайте.
Доступ к cookie и www.duolingo.com запрашивается отдельно после действия пользователя.
Переменные VITE_DUOFOLLOW_EXTENSION_ID и VITE_DUOFOLLOW_EDGE_EXTENSION_ID для Firefox не используются.

## Проверки

```powershell
npx playwright install firefox
npm run test:firefox
npm run test:firefox:extension
```

Первый тестовый набор проверяет сайт в Firefox с подставным каналом: главную, настройки, доступ,
политику, поиск, длинные надписи, диалоги, подсказки и навигацию. Локальный прогон использует один worker,
как CI: проверки нативного select и фокуса выполняются последовательно. Linux требует установки
системных зависимостей через npx playwright install --with-deps firefox.
Проверки клавиатурных подсказок получают фокус через Tab. Нативный select в тестах открывается
методом showPicker() из доверенного события указателя или клавиатуры. Открытое и закрытое состояния
проверяются через :open без подстановки. Общие проверки закрывают настоящее меню через blur:
для указателя движение мыши отсутствует, для клавиатуры фокус возвращается до завершения закрытия.
После восстановления подсказка закрывается клавишей Escape уже на странице. Сортировка проверяется
через selectOption() и порядок профилей в отдельном сценарии списка.

В используемой связке Playwright 1.57.0 / Firefox 144 клавиши страницы не закрывают нативное меню:
трассы после Escape и Enter сохраняют :open = true. Три проверки именно нативных клавиш явно
пропускаются только для Firefox с указанной причиной. Они продолжают выполняться в Chromium.
Реальное закрытие меню и восстановление подсказки не исключены из Firefox-набора; ручная приёмка
дополнительно проверяет нативные Escape и Enter. Пропуск автоматической проверки не подтверждает
эти способы закрытия автоматически. Ручной прогон 26 ноября 2026 года подтвердил ожидаемое поведение
трёх сценариев в Firefox 161.0 на Windows 11.
Ограничение соответствует [ответу команды Playwright](https://github.com/microsoft/playwright/issues/28860).

Для указателя picker открывается один раз на click после отмены стандартного mousedown, чтобы второе действие
браузера не закрыло его. Клавиатурная проверка дожидается прокрутки после установки фокуса, затем возвращает
фокус через Tab. Для первой ссылки используется переход вперёд и обратный Shift+Tab; это исключает
переход назад в панель браузера.
При сбое теста подсказки JSON-вложение native-select-state в trace содержит состояние picker и фокуса без значений полей.
Тест Firefox bridge выполняется также в Chromium: он использует настоящий код content script,
фонового bridge, адаптера и core с подставным SDK и ответами Duolingo.

test:firefox:extension запускает web-ext и временно устанавливает сборку в отдельный профиль Firefox.
Тест создаёт собственный HTTP-сервер на 127.0.0.1:5173. Порт должен быть свободен; работающий dev-сервер
предварительно останавливается. Проверяются cookie тестового профиля, сравнение, настройки,
быстрое подтверждение, чтение результата и запрет доступа к прежнему результату после перезагрузки.
Все ответы Duolingo заменены, реальные аккаунты и DELETE не используются.
DUOFOLLOW_FIREFOX_BINARY позволяет выбрать другой установленный Firefox для этого сценария.
Без переменной используется бинарный файл Playwright. Каталог firefox-test-results содержит только тестовые артефакты.
Профиль создаётся внутри собственного каталога теста. Завершение ожидает событие закрытия Firefox через
registerCleanup API web-ext; только затем каталог удаляется с ограниченными повторами при блокировках Windows.
Успешный результат выводится после очистки. Неудачное завершение процесса или очистки не скрывается.

Задание Firefox workflow Browser tests запускает lint, установленное расширение и интерфейс.
Прогон реального расширения дополняет контрактные тесты; тестовый профиль с заменёнными ответами
не подтверждает работу с текущим API Duolingo.

## Канал и границы доверия

Content script загружается только на маршрутах /duofollow/* разрешённых origin и в верхнем фрейме.
При отсутствии content script проверка соединения завершается через две секунды. Подтверждение получения
от content script продлевает ожидание ответа фона; тайм-аут операции по-прежнему контролирует клиент протокола.
В production manifest присутствует только https://hedgerock.github.io/duofollow/*.
Window-сообщения требуют совпадения source и origin; сайт остаётся недоверенным источником команд.
Нативный порт требует собственного extension ID, frameId 0 и браузерного tab ID.
Core сохраняет точные разрешённые маршруты: сравнение и отписка на главной, открытие настроек также на /access.

Случайный ID документа живёт в изолированном окружении content script. Он не попадает в Window-сообщения.
Команда сайта не может выбрать ID документа или вызвать внутреннее подтверждение стандартной отписки.
Разрыв связи завершает ожидание и подписку; повторная отправка записи автоматически не выполняется.
Проверка результата использует исходный request ID и тот же документ.

## Ручная приёмка и распространение

1. Установка в обычный профиль, доступ, определение аккаунта и одно автоматическое сравнение.
2. Возврат из политики и доступа без ложного отключения и лишнего сравнения.
3. Отзыв доступа, отказ в разрешении, повторная выдача, выход и смена аккаунта Duolingo.
4. Отмена и подтверждение стандартной отписки; быстрый режим с обязательным диалогом на сайте.
5. Перенос вкладки, открытие и повторное использование настроек рядом с текущей вкладкой.
6. Главная, настройки, политика, диалоги и уведомления на ширине 320, 796 и 1100 CSS px,
   при увеличенном тексте, масштабе 200 %, клавиатуре и уменьшении движения.
7. Наведение на сортировку, открытие меню и Escape без перемещения указателя: подсказка скрыта
   при открытом меню и восстанавливается после закрытия. Отмена сохраняет выбранную сортировку.
8. Повторное открытие меню, выбор следующего пункта и Enter без перемещения указателя:
   меню закрывается, сортировка меняется, подсказка восстанавливается.
9. Переход к сортировке через Tab, открытие меню и Escape без мыши: первый Escape закрывает меню
   и возвращает подсказку, второй скрывает подсказку. Фиксируются версия Firefox, ОС и результат.

```powershell
npm run extension:firefox:zip
```

Архив extension/dist-firefox/duofollow-connector-firefox-0.1.0.zip не содержит локальных origin.
Он предназначен для подготовки подписи или загрузки в AMO; создание ZIP не публикует расширение
и не делает неподписанную сборку постоянно устанавливаемой в обычный Firefox.
Gecko ID фиксирован как duofollow@hedgerock.github.io. Перед публикацией проверяются уникальность ID,
декларация data_collection_permissions, согласие на передачу данных Duolingo и публичная политика.
Отдельного публичного сервера для результатов, сессий или телеметрии не добавлено.

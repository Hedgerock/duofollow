# План проверок браузеров и производительности

## Состояние и область проверки

Материал задаёт критерии следующих итераций. Текущий набор Playwright проверяет сайт и установленное расширение
в Chromium с подставными ответами Duolingo. Linux-эталоны закреплены для этого окружения.
Поддержка Edge и Firefox подтверждается после проверки рабочего сценария и отображения интерфейса.

Каждый отчёт содержит commit, дату, ОС, версию браузера, версию сборки расширения, размер окна и масштаб текста.
Проверка вёрстки со смоделированным Connector и проверка установленного расширения получают отдельные результаты.

## Браузеры и расширение

| Среда                                | Проверка интерфейса                                                                 | Проверка интеграции                                                                |
| ------------------------------------ | ----------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------- |
| Chromium из закреплённого Playwright | Регрессии маршрутов, вёрстки, управления и Linux-скриншотов                         | Существующий тест установленного Connector с подставным API                        |
| Google Chrome Stable на ПК           | Проверка внешнего вида и основных действий в установленном браузере                 | Установка, выдача доступа, активная сессия Duolingo и подтверждённая отписка       |
| Microsoft Edge Stable на ПК          | Планируется тот же набор пользовательских сценариев, включая запуск канала `msedge` | Планируется установка сборки, проверка ID, разрешений, обмена сообщениями и записи |
| Firefox из Playwright                | Планируется проверка вёрстки и маршрутов с подставным каналом Connector             | Проверка Firefox-расширения входит в отдельную реализацию WebExtensions            |
| Mozilla Firefox Stable на ПК         | Планируется контрольный прогон опубликованной версии браузера                       | Планируется установка Firefox-сборки и проверка реальной сессии в том же профиле   |

Playwright использует собственную сборку Firefox. Результат её прогона дополняется проверкой установленного Firefox Stable.
Автоматическая загрузка тестового расширения выполняется в постоянном контексте Chromium. Способ установки
в Chrome и Edge учитывается при реализации их проверки. [Браузеры Playwright](https://playwright.dev/docs/browsers),
[проверка расширений](https://playwright.dev/docs/chrome-extensions).

Первое окружение проверки настольных сборок — Windows. Linux используется для закреплённых проверок CI.
Другие сочетания ОС и браузера получают статус поддержки после отдельного прогона с указанием окружения.

## Вёрстка и управление

Общая матрица охватывает следующие состояния.

| Область               | Проверяемые состояния                                                                                |
| --------------------- | ---------------------------------------------------------------------------------------------------- |
| Основные страницы     | Сравнение, настройки, доступ, политика, прямое открытие URL и возврат                                |
| Рабочая область       | Автоподключение, ручной ввод, загрузка, повторное сравнение, пустой список, частичный охват и ошибка |
| Подписки              | Все полученные, взаимные и невзаимные, поиск, сортировка, длинные и смешанные имена                  |
| Диалоги и уведомления | Подключение, отписка, отмена, подтверждение, несколько уведомлений, низкое окно                      |
| Оформление            | Светлый и тёмный режимы, все размеры и семейства шрифта, узоры статусов                              |
| Управление            | Мышь, клавиатура, видимый фокус, Escape, касание, уменьшение движения                                |
| Будущая локализация   | Длинные подписи, переключатель языков, RTL и возврат к LTR                                           |
| Новое оформление      | Те же сценарии после добавления выбора оформления                                                    |

Проверки геометрии используют ширины 320, 390, 650, 651, 760, 761, 796, 900, 1100 и 1440 CSS px.
Значения вокруг границ сетки включены в регрессионный набор. Отдельный сценарий при 280 CSS px проверяет
предусмотренную горизонтальную прокрутку страницы с минимальной шириной 320 CSS px.
Диалоги сохраняют доступные действия в окне высотой 250 CSS px. Настройки текста проверяются при
100 %, 112,5 % и 125 %. Масштаб браузера 200 % проверяется отдельно от настройки размера текста.

Карточки сохраняют выравнивание чисел и одинаковую закрытую высоту в пределах строки.
Раскрытие пояснения увеличивает соответствующую карточку. Скелет сохраняет геометрию загруженного состояния.
Фиксированные области, внутренний скролл и виртуальный список сохраняют доступность содержимого и кнопок.

Проверка CSS охватывает container queries, `:has()`, логические отступы, направление письма, полосы прокрутки,
обрезание текста и переходы. Различия браузеров проверяются в интерфейсе на заданных состояниях.
Эталоны скриншотов привязаны к браузеру, ОС, версии и шрифтам. Общими остаются проверки поведения и геометрии.

## Компьютеры небольшой и средней мощности

Целевые группы задают окружения измерений.

| Группа             | Ориентир для подбора реального ПК                                       | Что фиксируется в отчёте                                                  |
| ------------------ | ----------------------------------------------------------------------- | ------------------------------------------------------------------------- |
| Небольшая мощность | Компактный или старый ноутбук примерно с 4 ГБ ОЗУ и встроенной графикой | Модель CPU и GPU, число потоков, ОЗУ, ОС, режим питания и версия браузера |
| Средняя мощность   | Повседневный ноутбук или ПК примерно с 8 ГБ ОЗУ и встроенной графикой   | Те же сведения и одинаковые условия запуска                               |

Объём ОЗУ служит ориентиром выбора устройств. Подтверждённые характеристики поддержки определяются
по замерам на конкретных конфигурациях. Проверка учитывает питание от сети и режим экономии энергии,
если он заметно влияет на отклик.

Для повторяемого сравнения на одном компьютере планируются прогоны Chromium без замедления, с CPU 4× и 6×.
Коэффициент, модель хоста и режим питания сохраняются в отчёте. CPU throttling задаёт относительное
замедление на этом хосте. Итоговая оценка целевой группы опирается также на реальный ПК.
[Ограничения CPU throttling](https://developer.chrome.com/docs/devtools/performance/reference#throttle-the-cpu-while-recording).

## Сценарии и измерения производительности

Набор включает 1 000 и 10 000 тестовых профилей. Подставные ответы API позволяют измерить время работы интерфейса.
Загрузка из Duolingo измеряется отдельно вместе с сетевой задержкой.

Замеры охватывают первый показ списка, повторное сравнение, быстрый ввод и очистку поиска, смену вида,
сортировку, прокрутку в обе стороны, диалог отписки и возврат из настроек.
Отдельные прогоны используют инициалы, загруженные аватары, прогретый кеш и ошибку загрузки изображения.
Проверка на целевом ПК охватывает также анимации и длинные переводы.

Для одного набора данных выполняются прогрев и пять измеряемых прогонов одним воркером.
Отчёт содержит медиану и максимальное время ответа на ввод, поиска, смены вида и сортировки, длительные
задачи главного потока и пропуски кадров при прокрутке. Для памяти фиксируются исходный уровень и изменение
после одинаковых циклов действий, количество DOM-узлов, обработчиков и строк в окне виртуализации.

Действующий Chromium-тест проверяет до 24 смонтированных строк и рост после прогрева до 1,5 МиБ JS heap,
160 DOM-узлов и 24 обработчиков при одинаковом числе документов. Эти пороги относятся к его фиксированному сценарию.
Дополнительные прогоны с аватарами и другими браузерами получают собственные исходные замеры.

Первый этап измерений фиксирует базовый результат и бюджеты отклика для каждой целевой конфигурации.
Порог в CI вводится после оценки разброса повторных прогонов. Отчёт показывает изменение относительно
зафиксированного commit. Регрессия получает воспроизводимый сценарий и проверку в следующем исправлении.

## Включение в CI и критерий завершения

При добавлении Edge и Firefox их проекты включаются в проверки сайта. Тест установленного расширения
использует соответствующее браузеру окружение. Для частых pull request сохраняется короткий набор основных
сценариев. Расширенная матрица и замеры производительности запускаются отдельно по запросу или перед выпуском.

Для новой среды завершены проверка вёрстки, управление, установленное расширение и контроль реальной сессии.
В отчёте перечислены версии и результаты. Для аппаратных групп приложены воспроизводимый замер
и контрольный прогон на реальном устройстве. Лимиты и известные ограничения описаны в руководстве выпуска.

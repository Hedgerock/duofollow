# План развития

## Коды ошибок Connector

Следующая итерация. Различать окончание сессии, ограничение частоты запросов, тайм-аут и неожиданный формат ответа.
Сопоставить коды с действиями в интерфейсе и проверить переводы. Сценарий повторной проверки статуса описан в [Connector](connector.md#проверка-подключения).

## Охват и пагинация

Проверить, когда курсор Following и Followers возвращает новую страницу. Зафиксировать примеры ответов для повторившегося
курсора, повторившейся страницы и дубликатов ID. Покрыть тестами условия остановки пагинации. В интерфейсе пояснять причину
частичного охвата рядом со счётчиками.

## Линтинг и импорты

Подключить ESLint для TypeScript, React Hooks, кода Connector и тестов. Добавить команду `npm run lint` и запуск в CI.
Prettier продолжает проверять форматирование. ESLint проверяет правила кода и порядок импортов.

Использовать порядок групп импортов. Между группами оставлять одну пустую строку.

1. Встроенные модули Node.js (`node:*`).
2. Сторонние пакеты (`react`, `react-router`, `vitest`).
3. Внутренние модули DuoFollow.
4. Импорты только типов (`import type`).
5. Стили и другие импорты ради побочных эффектов. Сохранять их относительный порядок.

Внутренние импорты строить от корня репозитория через `@duofollow/*`. Указывать путь до конечного TS/TSX-модуля
без расширения файла. Примеры `@duofollow/src/pages/SettingsPage` и `@duofollow/extension/src/locales`.
У импортируемых ресурсов сохранять необходимое имя файла, например `@duofollow/privacy/index.html?raw`.

Настроить резолвинг алиаса в TypeScript и Vite и проверить его в Vitest и Playwright. Connector компилируется через `tsc`,
который оставляет пути импорта в выходном JS. Для перехода к алиасам в исходниках расширения обеспечить разрешение путей
при сборке и проверить загрузку распакованного `extension/dist` в Chrome.
[TypeScript `paths`](https://www.typescriptlang.org/tsconfig/paths.html)

Итерация завершена, когда проходят линтинг, проверка типов, тесты и обе сборки.

## Браузерные проверки в CI

Добавить запуск интеграционных тестов и сверку Linux-скриншотов для pull request. Использовать закреплённое окружение
Playwright. Нагрузочный тест оставить отдельным запуском.

## Автоматическое подключение аккаунта

После выдачи доступа к Connector DuoFollow определяет активный аккаунт Duolingo и запускает сравнение при открытии
главной страницы. В обычном сценарии поле имени заменяется карточкой подключённого аккаунта. Кнопка сравнения
обновляет результат для этого аккаунта.

1. Подтвердить источник профиля активной сессии на стороне Duolingo. Сейчас Connector определяет ID сессии,
   а текущий поиск `users{id,username,picture}` требует имя. Проверить поиск профиля по подтверждённому ID
   и получение имени пользователя и аватара, если он доступен.
2. После выдачи доступа и успешной проверки сессии показать подтверждённый аккаунт в шапке и запустить сравнение один раз.
   При повторном фокусе вкладки и переходах между страницами переиспользовать результат для той же сессии.
3. При выходе из аккаунта, смене сессии или отзыве доступа сбросить результат старого аккаунта и игнорировать его
   поздние ответы. При сбое определения профиля показывать причину и кнопку «Проверить снова».

Покрыть тестами выдачу доступа, повторную навигацию, смену аккаунта и отзыв во время запроса. Обновить описание
получения профиля в README и трёх версиях политики при выпуске автоматического подключения.

## Поддержка браузеров

| Браузер              | Статус   | Цель                                                                                      |
| -------------------- | -------- | ----------------------------------------------------------------------------------------- |
| Google Chrome (ПК)   | Работает | Основная сборка расширения Manifest V3 и текущая связь с сайтом DuoFollow.                |
| Microsoft Edge (ПК)  | В плане  | Проверить текущую Chromium-сборку в `edge://extensions` и выбрать способ распространения. |
| Mozilla Firefox (ПК) | В плане  | Подготовить сборку WebExtensions и канал связи с интерфейсом для Firefox.                 |

- **Edge.** Проверить установку распакованного расширения, фактический ID, передачу сообщений и запросы Duolingo с сессией Edge.
  Для публикации заранее сверить ID расширения, которое установит пользователь, с ID, используемым сайтом.
  [Документация Microsoft](https://learn.microsoft.com/en-us/microsoft-edge/extensions-chromium/developer-guide/port-chrome-extension)
- **Firefox.** Запускать фоновый код через `background.scripts`. Для сайта на GitHub Pages добавить content script,
  который подключается только на страницах DuoFollow и передаёт проверенные команды фоновому скрипту расширения.
  Прямой вызов `runtime.sendMessage` с веб-страницы через `externally_connectable.matches` в Firefox пока недоступен.
  [Фоновые скрипты Firefox](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/manifest.json/background),
  [статус поддержки прямых сообщений](https://bugzilla.mozilla.org/show_bug.cgi?id=1319168)

Критерий поддержки нового браузера — расширение устанавливается, сайт сравнивает списки в текущей сессии Duolingo, показывает охват,
восстанавливает сохранённый аккаунт и сообщает об ошибках. Для функций записи потребуется также отдельная ручная проверка в каждом поддерживаемом браузере.

## Интернационализация

Следующий язык — испанский. Для каждого нового языка обновить словари сайта и Connector, добавить перевод политики и
проверить переключение языка, формат счётчиков, переход на английский при отсутствии перевода и длинные подписи на ширине 320 пикселей.
Для языков с письмом справа налево добавить настройку `dir` на корневом элементе и проверить расположение элементов.

# Общая логика расширения и визуальный слой

## Ревизия от 22 ноября 2026 года

Chrome и Edge используют одну сборку Manifest V3 и одни исходные файлы. Отличия сайта ограничены ID расширения
и инструкциями подключения. По сообщению разработчика автоматические и ручные проверки Edge прошли без обнаруженных дефектов.
Результат относится к проверенному окружению; версия браузера и ОС в сообщении не указаны.

Материал фиксирует результаты ревизии и план следующих итераций. Новые границы модулей и поддержка Safari
получают ADR при реализации. [Правила ADR](adr-guidelines.md)

## Общая логика расширения

После ADR-0016 общий core находится в `extension/src/core`. Chrome и Edge используют один Chromium-адаптер.
Firefox использует отдельный адаптер, фоновую страницу и content script.
[Реализация и границы приёмки](firefox.md).
Разработчик подтвердил ручной прогон Firefox 161.0 на Windows 11 26 ноября 2026 года, включая
управление нативным select и подсказками с клавиатуры. Дефектов не обнаружено.
[Результат проверки](../reviews/2026-11-25-firefox.md#ручная-проверка-от-26-ноября-2026-года).

| Область                | Текущее состояние                                                                             | Граница при переносе                                    |
| ---------------------- | --------------------------------------------------------------------------------------------- | ------------------------------------------------------- |
| DTO и валидаторы       | Сайт и расширение используют общие типы и проверки                                            | Общий протокол и валидация неизвестных данных           |
| Разбор ответов и охват | `duolingoPayload.ts` разбирает профили и списки                                               | Общие правила сравнения                                 |
| Сессия                 | `core/duolingoSession.ts` проверяет аккаунт и получает cookie через платформу                 | Браузерный источник сессии и общая проверка аккаунта    |
| Пауза запросов         | `core/duolingoRateLimit.ts` сохраняет срок через переданный session storage                   | Общие правила HTTP 429 и адаптер хранения               |
| Отписка                | `core/unfollowRequests.ts` управляет операцией, журналом и вызывает возможность открытия окна | Общий сценарий и адаптер подтверждения                  |
| Worker                 | `background.ts` выбирает адаптер, `core/createConnector.ts` проверяет источник и команды      | Точка входа, платформа и общие правила допуска          |
| Клиент сайта           | `DuoFollowConnector` проверяет ответы, `chromiumTransport` доставляет сообщения               | Клиент команд и заменяемый транспорт запросов и событий |

Источники: [worker](../../extension/src/background.ts), [сессия](../../extension/src/core/duolingoSession.ts),
[пауза](../../extension/src/core/duolingoRateLimit.ts), [отписка](../../extension/src/core/unfollowRequests.ts),
[клиент сайта](../../src/api/extension/DuoFollowConnector.ts).

Core находится внутри репозитория и содержит правила, общие для поддерживаемых браузеров.
Адаптеры отвечают за разрешения, cookie, хранение, вкладки, окна и доставку сообщений.
Реальные различия определяют состав адаптеров. Идентичные операции Chrome и Edge используют один адаптер.
Выделение самостоятельного npm-пакета оценивается при появлении независимого потребителя или цикла выпуска.

Подготовительный перенос завершён. Контрактные проверки охватывают отказ в разрешениях,
отмену, одноразовое подтверждение, восстановление после перезапуска и общую паузу запросов.
Браузерные адаптеры выполняют один набор контрактных сценариев. Ручная проверка установленной сборки
в Chrome и Edge остаётся частью выпуска. [Контракты](browser-adapter-contracts.md) ·
[ADR-0016](../decisions/records/0016-browser-core-and-adapters.md)

Проверка origin, верхнего фрейма и источника подтверждения сохраняется на стороне расширения.
Привязка операции к документу сохраняет защиту от подтверждения из другой вкладки и повторного использования команды.
Замена транспорта требует проверки этих свойств в целевом браузере.

## Визуальный слой

Основной [CSS сайта](../../src/style.css) содержит около 2300 строк. В нём находятся палитры, общий макет,
карточки, список, диалоги, подсказки и уведомления. [CSS расширения](../../extension/assets/access.css)
повторяет часть цветовых переменных. Страница подтверждения содержит дополнительные правила внутри
[HTML](../../extension/assets/unfollow-confirmation.html).

Перед реализацией нового оформления планируется внутренний модуль стилей:

- Семантические токены цветов, отступов, радиусов, фокуса и длительности переходов.
- Базовые правила и макет сайта.
- Стили общих элементов: кнопок, панелей, диалогов, подсказок и уведомлений.
- Стили предметных областей: аккаунта, счётчиков, списка и настроек.
- Небольшой набор общих токенов для сайта и страниц расширения.

Визуальный модуль относится к UI. Управление фокусом, клавиатура, согласие, отмена и другие правила UX
остаются в компонентах и сценариях. Повторяющиеся правила поведения выделяются по фактическому использованию.
Механический перенос CSS сохраняет оформление; новый дизайн вводится следующей итерацией.

Общие токены подключаются локально в сборках сайта и расширения. Настройки каждого окружения сохраняют
свой источник состояния. [Резервная политика без JavaScript](../../privacy/privacy.css) остаётся читаемой самостоятельно.
Разделение CSS проверяется скриншотами, геометрией, порядком каскада, темами, размером текста,
уменьшением движения и управлением с клавиатуры. Подключение CSS Modules оценивается по необходимости изоляции селекторов.

## Safari

Safari входит в целевой набор вместе с Chrome, Edge и Firefox. Первый этап касается настольного Safari на macOS.
По данным [StatCounter за октябрь 2026 года](https://gs.statcounter.com/browser-market-share/desktop),
доля Safari в настольном веб-трафике составляет 7,83 %. Это оценка трафика, а не размера аудитории DuoFollow.

Исследовательский этап проверяет следующие условия.

1. Совместимость используемых API и минимальную версию Safari. В текущем коде есть `storage.session`, работа
   с cookie и привязка операции к документу. Apple указывает поддержку `storage.session` с Safari 16.4
   и отсутствие `tabs.move`, который сейчас используется при размещении уже открытых настроек рядом с сайтом.
2. Доставку сообщений и идентификатор расширения. Apple документирует `externally_connectable`,
   сообщения и внешние порты. Идентификатор Safari включает bundle ID и team ID.
3. Выдачу и отзыв разрешений, проверку реальной сессии, сравнение и оба режима подтверждения отписки.
4. Упаковку, подпись, TestFlight и распространение. Доступны инструменты Xcode и веб-упаковщик
   App Store Connect. Веб-упаковщик позволяет подготовить пакет без Mac и Xcode при участии в Apple Developer Program.
5. Вёрстку, фокус, скролл, диалоги и анимации. Playwright WebKit дополняет проверку в установленном Safari на macOS.

Источники: [совместимость API](https://developer.apple.com/documentation/safariservices/assessing-your-safari-web-extension-s-browser-compatibility),
[сообщения Safari](https://developer.apple.com/documentation/safariservices/messaging-between-a-webpage-and-your-safari-web-extension),
[упаковка через App Store Connect](https://developer.apple.com/documentation/safariservices/packaging-and-distributing-safari-web-extensions-with-app-store-connect),
[ограничения Playwright WebKit](https://playwright.dev/docs/browsers#webkit).

Статус Safari остаётся исследовательским до проверки условий и наличия окружения для реального Safari.
Результат WebKit с подставным каналом подтверждает соответствующие свойства сайта. Поддержка расширения
подтверждается отдельным прогоном установленной сборки.
Мобильный Safari получает собственные критерии для сенсорного управления, окон и жизненного цикла.

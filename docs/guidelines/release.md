# Проверки и выпуск

## Проверки перед коммитом

```bash
npm ci
npm run lint
npm test
npm run format:check
npm run build
npm --prefix extension run build
```

Vitest проверяет полный и неполный Followers, дедупликацию, обработку отказов и тайм-аутов, сохранение аккаунта, окно виртуализации
на 10 000 записях и повторный показ битого аватара. В тестах API используются подставные ответы. Сборка расширения проверяет TypeScript
и собирает скрипты фонового процесса, страницы доступа и окна подтверждения через esbuild. Манифест, локали и PNG-иконки копируются в `extension/dist`. Тесты Connector проверяют коды для 401, 403 и 429,
тайм-ауты, несовместимые ответы и неизвестный исход отписки. Проверки интерфейса сверяют локализацию, повторную проверку
подключения и сохранение карточки при неподтверждённой отписке. Тесты импортов проверяют порядок групп, сохранение последовательности
импортов с побочными эффектами и запрет относительных путей. Перед публикацией GitHub Pages CI запускает ESLint, Vitest,
Prettier и обе сборки. Тесты Connector проверяют общий кэш сессии, паузу после HTTP 429 и смену аккаунта.
Chromium проверяет, какие источники изображений разрешает политика страницы, и что ошибочный ответ сравнения сохраняет предыдущий список.
Тест на ширине 1100 CSS px сравнивает высоту закрытых карточек, когда метка «Частично» есть только у одного счётчика.
Тест повторной загрузки сверяет высоту карточек со скелетом на ширинах 1100 и 320 CSS px, включая двухстрочные подписи.
Отдельный сценарий при ширине 320 CSS px проверяет раскрытие пояснений к счётчикам, плавное закрытие при уходе фокуса,
неизменную высоту соседней карточки, подсветку при наведении и отключение переходов при уменьшении движения.
Украинское пояснение остаётся внутри карточки при размере текста 125 %
на ширинах 320 и 1100 CSS px. Тесты отписки проверяют одноразовое подтверждение, отмену, изменение сессии и доступа,
различие полного и частичного Following и восстановление исхода после перезапуска worker.

### Браузерные и скриншотные тесты

Playwright запускает собранный сайт и подставляет ответы Connector. Сценарии проверяют фильтры, подсказку при наведении
и с клавиатуры, подтверждение отписки, поведение при неполных данных и ширину страницы на 320 и 280 CSS px.
Тесты также проверяют счётчик до и после поиска, пояснение у отключённого фильтра и сортировку рядом с поиском на ширине 320 CSS px.
Переходы между страницами проверяются при ширине 1100 и 320 CSS px. Тест сверяет положение шапки и подвала,
прокрутку с клавиатуры и положение контента после перехода. При размере текста 125 % тесты проверяют шапку с длинным ником
на ширинах 320, 551, 673 и 1100 CSS px, русский заголовок с пятизначным счётчиком и украинскую кнопку повторной проверки
в окне 320 × 250 CSS px. Для длинного профиля в диалоге отписки тест проверяет фокус на «Отмена» и возврат фокуса в карточку.
Отдельный сценарий устанавливает локальную сборку Connector в изолированный профиль Chromium и подставляет ответы Duolingo.
Он проверяет окно подтверждения, отмену без записи, переключение быстрой отписки и результат одного
`DELETE` после потери ответа.

Для локальной проверки команда `npx playwright install chromium` устанавливает Chromium, а `npm run test:integration`
запускает интеграционные тесты. Скриншоты сравниваются в Docker. В [compose.test.yml](../../compose.test.yml) закреплены
версия Playwright и архитектура Linux AMD64.

```sh
npm run test:browser:docker
```

Первая запись эталонов и их обновление после согласованного изменения интерфейса выполняются следующей командой.

```sh
npm run test:browser:docker:update-snapshots
```

Обновлённые изображения доступны в `e2e/snapshots/linux`. После просмотра выполняется повторный прогон обычной командой.
PNG входят в коммит после успешного прогона. При отсутствии эталона обычный запуск завершается ошибкой.

Workflow [Browser tests](../../.github/workflows/browser-tests.yml) запускает ту же команду на pull request.
Playwright выполняет проверки одним воркером. Результат виден в Checks. При сбое артефакт
`playwright-test-results` на странице запуска содержит доступные трассировки и файлы сравнения скриншотов.
Решение зафиксировано в [ADR-0002](../decisions/records/0002-browser-tests-in-ci.md).

### Нагрузка на виртуальный список

Отдельный тест Chromium загружает 10 000 тестовых профилей. После шести циклов прогрева он прокручивает список,
меняет вид, фильтр и порядок, открывает подсказку, уходит в настройки и возвращается к результату. Он проверяет,
что одновременно остаётся до 24 карточек и сравнение с Connector выполняется ровно один раз.

Тест выводит в консоль исходный замер после прогрева и четыре замера через каждые 10 циклов после сборки мусора.
Команда `npm run test:load -- --reporter=list,html` включает замеры во вложение HTML-отчёта.
Относительно исходного замера допустим рост до 1,5 МиБ JS heap, 160 DOM-узлов и 24 обработчиков.
Число документов должно совпадать. Замеры охватывают страницу Chromium и её виртуальный список с инициалами вместо аватаров.

Локальный запуск через `npm run test:load` требует установленного Chromium. В закреплённом Linux-окружении тест запускается
через Docker.

```sh
npm run test:load:docker
```

### Ручная проверка перед выпуском

1. **Доступ.** В чистом профиле Chrome запросы к Duolingo отсутствуют до выдачи доступа и после отказа. После выдачи доступа
   кнопка сравнения запускает запрос. Кнопка «Отключить доступ» и отзыв разрешений через Chrome очищают имя и результаты.
2. **Сравнение.** В Network инспектора service worker видны запросы профиля, Following и Followers для активного аккаунта.
   Профиль в шапке и охват обоих списков соответствуют результату. Обновление страницы запускает одно автоматическое сравнение.
3. **Список.** Проверка включает поиск без совпадений, оба направления сортировки, ссылку на профиль, выделение имени
   и прокрутку вниз и обратно. Запросы аватаров проверяются при выключенной опции **Disable cache**. Переключатель меняет
   виды списка, легенда соответствует отметкам, а арабские имена рядом с латинскими идентификаторами и японский текст
   отображаются корректно. При неполном Followers фильтр невзаимных недоступен. При старой версии Connector сайт
   показывает доступные данные и предлагает обновить расширение.
4. **Отписка.** При открытии окна с клавиатуры фокус находится на кнопке «Отмена». Escape закрывает окно и возвращает фокус
   в карточку. Проверка после подтверждения охватывает ответ Duolingo, исчезновение карточки, обновление счётчиков
   и позицию списка. Повторное сравнение показывает обновлённые данные. При уменьшении движения карточка исчезает сразу.
5. **Уведомления.** Интерфейс показывает уведомления об успехе и ошибке. Кнопка закрывает уведомление, а наведение
   и фокус приостанавливают таймер.
6. **Навигация.** Логотип возвращает с политики и страницы доступа на `/duofollow/`. Адрес работает после обновления.
   При прямом открытии политики из внешней ссылки логотип и кнопка «К сравнению» загружают главную, где подключённый
   Connector проходит проверку без предупреждения.
   При неизменном доступе сохраняются результаты без нового сравнения и уведомления. Шапка и подвал остаются на месте
   при прокрутке главной и политики. Каждая открытая страница начинается сверху.
7. **Отключённый Connector.** Предупреждение проверяется на ширинах 320 и 390 px и в низком окне. Инструкция открывается
   и закрывается с клавиатуры. Верх окна сохраняет положение, а кнопки остаются доступны. Кнопка «Проверить снова»
   показывает результат проверки. Сценарий повторяется с включённым уменьшением движения.
8. **Результаты на узком экране.** На ширине 320 CSS px счётчики, поиск и сортировка помещаются без горизонтальной прокрутки.
   При поиске плашка рядом с заголовком показывает число совпадений из размера выбранного списка. При ширине окна 280 px
   страница сохраняет ширину 320 px, а кнопки модального окна остаются видимыми.
9. **Настройки оформления.** Страница настроек открывается напрямую и после обновления. На ширине 320 CSS px размер 125 %,
   смена шрифта и узоры корректно применяются к сравнению. Позиции строк и вид отметок проверяются в обеих темах.
   После обновления страницы выбор сохраняется.

## Готовность публичного выпуска Connector

Критерии относятся к будущей публичной сборке. ZIP для локальных проверок собирается по инструкции ниже.

1. Допустимость чтения списков подписок, отображения аватаров, отписки после подтверждения и выбранного оформления
   уточняется у Duolingo. Ответ и применимые условия распространения фиксируются и определяют сценарий выпуска.
   [Условия использования Duolingo](https://www.duolingo.com/terms)
2. Сценарии [безопасной отписки](roadmap.md#безопасная-отписка), получение согласия, отзыв доступа и смена аккаунта
   проверяются на установленном Connector. Значение сессионного cookie отсутствует в сообщениях сайту, хранилище и логах.
3. В магазинной сборке `externally_connectable.matches` ограничен поддерживаемыми маршрутами DuoFollow. Проверка охватывает
   главную страницу, экран управления доступом и отклонение команд с других страниц того же хоста.
   Service worker проверяет источник и маршрут.
4. Версия ZIP берётся из манифеста и совпадает с версиями npm-пакета расширения и его lock-файла. Из
   `extension/package.json` удаляются шаблонные поля и скрипт `test`.
5. После появления страницы Chrome Web Store оба README содержат ссылку и короткую инструкцию по установке и выдаче
   доступа. Инструкция, политика конфиденциальности и декларации магазина соответствуют распространяемой сборке.

## ZIP для Chrome Web Store

После установки зависимостей сборка запускается из корня репозитория.

```bash
npm --prefix extension run zip
```

Команда компилирует магазинную сборку и помещает архив в `extension/dist/duofollow-connector-<version>.zip`.
Версия берётся из `extension/manifest.json`. Для архивации используется системный `tar.exe` в Windows или `zip` в macOS и Linux.

При первой публикации ZIP загружается через **Add new item** в [панели разработчика Chrome Web Store](https://chrome.google.com/webstore/devconsole).
Сборка обновления требует увеличения `version` в манифесте.

## GitHub Pages

### Предпросмотр ссылки

У главной страницы есть статические заголовок, описание, канонический URL и метаданные Open Graph в `index.html`.
Карточка использует [изображение 1200 × 630 px](../../public/duofollow-preview.png). После деплоя проверяется доступность
главной страницы и изображения по HTTPS. Браузерный тест проверяет эти метаданные с отключённым JavaScript.
Текст карточки задан на английском. После загрузки заголовок вкладки соответствует языку сайта.

### Публичная политика конфиденциальности

React Router показывает главную, политику, управление доступом и настройки внутри общего `Outlet`. Для настроек сборка создаёт `dist/settings/index.html`.
Vite сохраняет отдельные HTML-точки входа для прямых ссылок и обновления страницы на GitHub Pages.
Страницы политики содержат полный текст до загрузки React. После деплоя доступность
`https://hedgerock.github.io/duofollow/privacy/` проверяется в окне без входа. Это английская версия и URL для поля
«Политика конфиденциальности» в кабинете Chrome Web Store. Украинская и русская версии доступны по
`/duofollow/privacy/uk/` и `/duofollow/privacy/ru/`. Ссылка есть в нижней части сайта и на экране выдачи доступа.
Изменения обработки данных отражаются на всех трёх страницах и в декларациях кабинета.

### Настройка деплоя

1. Источником публикации в **Settings → Pages → Build and deployment → Source** служит **GitHub Actions**.
2. Переменная репозитория `VITE_DUOFOLLOW_EXTENSION_ID` задаётся в **Settings → Secrets and variables → Actions → Variables**.
   Значение соответствует ID распространяемого Chrome-расширения.
3. Workflow запускается при пуше в `main` или вручную через Actions. Он проверяет код через ESLint, Vitest и Prettier,
   проверяет сборку Connector, передаёт ID в Vite и публикует папку `dist`. При пустом ID шаг сборки сайта останавливается с сообщением об ошибке.
   Браузерные и скриншотные проверки перед публикацией запускаются отдельно через Docker Compose.

Файл `.env.local` используется локально. Значение `VITE_*` попадает в клиентскую сборку, поэтому здесь нужен публичный ID расширения.
Публикация использует стабильный ID распространяемой сборки, чтобы сайт работал с установленным расширением.
Смена адреса Pages требует сверки `base` в `vite.config.ts`, URL метаданных в `index.html`, списка
`externally_connectable.matches` в манифесте и `pagePaths` в service worker. Артефакт GitHub Pages берётся из `dist` сайта.
Сборка Connector сохраняется в `extension/dist`.

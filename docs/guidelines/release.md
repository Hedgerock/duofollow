# Проверки и выпуск

## Проверки перед коммитом

```bash
npm ci
npm run lint
npm test
npm run format:check
npm run build
npm --prefix extension run build
```

Vitest проверяет полный и неполный Followers, дедупликацию, обработку отказов и тайм-аутов, сохранение аккаунта, окно виртуализации
на 10 000 записях и повторный показ битого аватара. В тестах API используются подставные ответы. Сборка расширения проверяет TypeScript
и собирает скрипты фонового процесса и страницы доступа через esbuild. Манифест, локали и PNG-иконки копируются в `extension/dist`. Тесты Connector проверяют коды для 401, 403 и 429,
тайм-ауты, несовместимые ответы и неизвестный исход отписки. Проверки интерфейса сверяют локализацию, повторную проверку
подключения и сохранение карточки при неподтверждённой отписке. Тесты импортов проверяют порядок групп, сохранение последовательности
импортов с побочными эффектами и запрет относительных путей. Перед публикацией GitHub Pages CI запускает ESLint, Vitest,
Prettier и обе сборки. Тесты Connector проверяют общий кэш сессии, паузу после HTTP 429 и смену аккаунта.
Chromium проверяет, какие источники изображений разрешает политика страницы, и что ошибочный ответ сравнения сохраняет предыдущий список.

### Браузерные и скриншотные тесты

Playwright запускает собранный сайт и подставляет ответы Connector. Сценарии проверяют фильтры, подсказку при наведении
и с клавиатуры, подтверждение отписки, поведение при неполных данных и ширину страницы на 320 и 280 CSS px.
Тесты также проверяют счётчик до и после поиска, пояснение у отключённого фильтра и сортировку рядом с поиском на ширине 320 CSS px.
Переходы между страницами проверяются при ширине 1100 и 320 CSS px. Тест сверяет положение шапки и подвала,
прокрутку с клавиатуры и положение контента после перехода. При размере текста 125 % тесты проверяют шапку с длинным ником
на ширинах 320, 551, 673 и 1100 CSS px, русский заголовок с пятизначным счётчиком и украинскую кнопку повторной проверки
в окне 320 × 250 CSS px. Для длинного профиля в окне отписки тест проверяет фокус на «Отмена» и возврат фокуса в карточку.

Локально установи Chromium через `npx playwright install chromium` и запусти `npm run test:integration`.
Скриншоты сравнивай в Docker. В [compose.test.yml](../../compose.test.yml) закреплены версия Playwright и архитектура Linux AMD64.

```sh
docker compose -f compose.test.yml run --rm browser-tests
```

Для первой записи эталонов и после согласованного изменения интерфейса запусти следующую команду.

```sh
docker compose -f compose.test.yml run --rm browser-tests sh -c "npm ci --no-audit --no-fund && npm run test:browser -- --project=visual --update-snapshots=all"
```

Просмотри обновлённые изображения в `e2e/snapshots/linux` и повтори обычный запуск. После успешного прогона добавь PNG
в коммит. При отсутствии эталона обычный запуск завершится ошибкой.

### Нагрузка на виртуальный список

Отдельный тест Chromium загружает 10 000 тестовых профилей. После шести циклов прогрева он прокручивает список,
меняет вид, фильтр и порядок, открывает подсказку, уходит в настройки и возвращается к результату. Он проверяет,
что одновременно остаётся до 24 карточек и сравнение с Connector выполняется ровно один раз.

Тест выводит в консоль исходный замер после прогрева и четыре замера через каждые 10 циклов после сборки мусора.
Чтобы открыть замеры во вложении HTML-отчёта, запусти `npm run test:load -- --reporter=list,html`.
Относительно исходного замера допустим рост до 1,5 МиБ JS heap, 160 DOM-узлов и 24 обработчиков.
Число документов должно совпадать. Замеры охватывают страницу Chromium и её виртуальный список с инициалами вместо аватаров.

Локально после установки Chromium запусти `npm run test:load`. Для проверки в закреплённом Linux-окружении используй Docker.

```sh
docker compose -f compose.test.yml run --rm browser-tests sh -c "npm ci --no-audit --no-fund && npm run test:load"
```

### Ручная проверка перед выпуском

1. Открой сайт в чистом профиле Chrome и проверь отсутствие обращений к Duolingo до выдачи доступа и после отказа.
   Разреши доступ, запусти сравнение и нажми «Отключить доступ» в настройках Connector. Сайт должен очистить имя
   и результаты. Проверь такой же сценарий при отзыве разрешения через Chrome.
2. Сравни подписки своего аккаунта. В Network инспектора service worker проверь запросы профиля, Following и Followers.
   Сверь профиль в шапке и охват подписок и подписчиков. Обновление страницы должно запустить одно автоматическое сравнение.
3. Проверь поиск без совпадений, оба направления сортировки, ссылку на профиль и выделение имени. Прокрути список вниз и обратно.
   При проверке сетевых запросов за аватарами оставь опцию **Disable cache** выключенной.
   Переключи виды списка, проверь легенду, арабские имена рядом с латинскими идентификаторами и японский текст.
   При неполном Followers фильтр невзаимных должен быть недоступен. При старой версии Connector сайт показывает доступные данные и предлагает обновить расширение.
4. Открой окно отписки с клавиатуры. Фокус должен быть на «Отмена». Escape закрывает окно и возвращает фокус в карточку.
   После подтверждения проверь ответ Duolingo, исчезновение карточки, счётчики и позицию списка. Повторное сравнение должно
   показать обновлённые данные. При включённом уменьшении движения карточка исчезает сразу.
5. Проверь уведомления об успехе и ошибке, закрытие кнопкой и паузу таймера при наведении и фокусе.
6. Перейди с главной на политику и страницу управления доступом, затем вернись по логотипу. URL главной должен оканчиваться
   на `/duofollow/` и работать после обновления. Возврат при неизменном доступе сохраняет результаты без нового сравнения и уведомления.
   Прокрути контент на главной и в политике. Шапка и подвал должны оставаться на месте, а каждая открытая страница начинаться сверху.
7. Отключи Connector и проверь предупреждение на ширине 320 и 390 пикселей и в низком окне. Раскрой и сверни инструкцию
   клавиатурой. Верх окна должен оставаться на месте, а кнопки быть доступны. Нажми «Проверить снова» и проверь сообщение
   о результате. Повтори с включённым уменьшением движения.
8. Открой результаты на ширине 320 CSS px. Счётчики, поиск и сортировка должны помещаться без горизонтальной прокрутки.
   При поиске плашка справа от заголовка показывает число совпадений из размера выбранного списка.
   На 280 px страница должна сохранять ширину 320 px. Проверь, что кнопки модалки остаются внутри видимой области.
9. Открой настройки напрямую и обнови страницу. На ширине 320 CSS px выставь размер 125 %, смени шрифт и включи узоры.
   Вернись к сравнению, проверь позиции строк и внешний вид отметок в обеих темах. После обновления страницы выбор должен сохраниться.

## ZIP для Chrome Web Store

После установки зависимостей запусти из корня репозитория:

```bash
npm --prefix extension run zip
```

Команда компилирует магазинную сборку и помещает архив в `extension/dist/duofollow-connector-<version>.zip`.
Версия берётся из `extension/manifest.json`. Для архивации используется системный `tar.exe` в Windows или `zip` в macOS и Linux.

Для первой публикации выбери **Add new item** в [панели разработчика Chrome Web Store](https://chrome.google.com/webstore/devconsole)
и загрузи ZIP. Перед сборкой обновления увеличь `version` в манифесте.

## GitHub Pages

### Предпросмотр ссылки

У главной страницы есть статические заголовок, описание, канонический URL и метаданные Open Graph в `index.html`.
Карточка использует [изображение 1200 × 630 px](../../public/duofollow-preview.png). После деплоя проверь главную
и доступность изображения по HTTPS. Браузерный тест проверяет эти метаданные с отключённым JavaScript.
Текст карточки задан на английском. После загрузки заголовок вкладки соответствует языку сайта.

### Публичная политика конфиденциальности

React Router показывает главную, политику, управление доступом и настройки внутри общего `Outlet`. Для настроек сборка создаёт `dist/settings/index.html`.
Vite сохраняет отдельные HTML-точки входа для прямых ссылок и обновления страницы на GitHub Pages.
Страницы политики содержат полный текст до загрузки React. После деплоя открой
`https://hedgerock.github.io/duofollow/privacy/` в окне без входа. Это английская версия и URL для поля
«Политика конфиденциальности» в кабинете Chrome Web Store. Украинская и русская версии доступны по
`/duofollow/privacy/uk/` и `/duofollow/privacy/ru/`. Ссылка есть в нижней части сайта и на экране выдачи доступа.
При изменении обработки данных обнови все три страницы и декларации в кабинете.

### Настройка деплоя

1. В репозитории открой **Settings → Pages → Build and deployment → Source** и выбери **GitHub Actions**.
2. В **Settings → Secrets and variables → Actions → Variables** создай переменную репозитория `VITE_DUOFOLLOW_EXTENSION_ID`
   со значением ID распространяемого Chrome-расширения.
3. Workflow запускается при пуше в `main` или вручную через Actions. Он проверяет код через ESLint, Vitest и Prettier,
   проверяет сборку Connector, передаёт ID в Vite и публикует папку `dist`. При пустом ID шаг сборки сайта останавливается с сообщением об ошибке.
   Браузерные и скриншотные проверки перед публикацией запускаются отдельно через Docker Compose.

Файл `.env.local` используется локально. Значение `VITE_*` попадает в клиентскую сборку, поэтому здесь нужен публичный ID расширения.
Для публикации используй стабильный ID одной распространяемой сборки, чтобы посетители сайта могли установить совместимое расширение.
Для другого адреса Pages сверь `base` в `vite.config.ts`, URL метаданных в `index.html`, список `externally_connectable.matches` в манифесте,
а также `pagePaths` в service worker. Артефакт GitHub Pages берётся из `dist` сайта. Сборка Connector сохраняется в `extension/dist`.

# Руководство разработчика DuoFollow

Неофициальное приложение на React и TypeScript для поиска невзаимных подписок Duolingo.

## DuoFollow Connector

DuoFollow и открытая сессия Duolingo работают в одном профиле Chrome. Сайт отправляет команды через
`chrome.runtime.sendMessage`. Фоновый скрипт использует разрешение на `www.duolingo.com` для запросов к Duolingo.
Для сравнения в форму вводится имя пользователя.

Коннектор принимает команды с `https://hedgerock.github.io`, `http://localhost:5173` и `http://127.0.0.1:5173`.
Команда `UNFOLLOW` принимается от страницы DuoFollow, открытой во вкладке по пути `/duofollow/`, `/duofollow` или `/duofollow/index.html`.

Сборка копирует манифест и четыре PNG-иконки из `extension/icons` в `extension/dist`.

## Сравнение

1. `GET_FOLLOWING_SUMMARY` получает имя из формы. Коннектор убирает пробелы по краям и начальный `@`, находит профиль и получает его числовой ID.
2. Коннектор параллельно запрашивает по одной странице Following и Followers с `pageSize=500` и `viewerId` этого аккаунта.
   В проверенных прогонах запрос с курсором повторял первую выборку. Сейчас счётчик «Проверено» показывает количество уникальных
   подписок в полученной странице, а общий счётчик берётся из `totalUsers`.
3. Взаимные подписки — пересечение по `userId`. Список невзаимных показывается, когда `cursor === null` у Followers
   и число уникальных подписчиков равно `totalUsers`. При неполном Followers счётчик невзаимных показывает «—».

После успешного сравнения сайт сохраняет имя в `localStorage` под ключом `duofollow.accountUsername`. При обновлении страницы
сравнение запускается автоматически. Редактирование поля оставляет текущий результат на экране. Каждый новый запрос показывает
скелет, а при ошибке возвращается предыдущий результат.

### Список и аватары

- Поиск фильтрует полученные карточки по имени и `@username`. Свободная часть карточки открывает профиль, а имя и идентификатор
  можно выделить и скопировать. Блок в шапке открывает профиль из результата сравнения.
- Виртуальный список отрисовывает видимые строки по 68 px и до четырёх запасных строк с каждой стороны.
- Аватары в карточках загружаются лениво. Коннектор добавляет `https:` к адресам вида `//…` и размер `/medium` к базовым адресам
  известных CDN Duolingo. При ошибке загрузки показываются инициалы. На повторном появлении карточки запрос к тому же битому URL
  пропускается до 60 секунд. Кеш ошибок хранит до 512 адресов в памяти страницы.
- В правом верхнем углу отображаются до трёх уведомлений одновременно. Таймер закрытия ставится на паузу при наведении и фокусе.

## Отписка от одного пользователя

Модальное окно показывает аватар и имя выбранного профиля, а также аккаунт, с которого удаляется подписка. Команда `UNFOLLOW`
отправляется после нажатия «Отписаться». Коннектор заново запрашивает Following и проверяет, есть ли цель среди полученных записей.

Карточка удаляется после успешного HTTP-ответа с `{"successful":true}`. Видимая строка плавно исчезает, затем обновляются счётчики.
При системной настройке уменьшения движения или когда строка за пределами окна списка результат обновляется сразу. При отказе или тайм-ауте карточка
остаётся на месте, а уведомление предлагает повторить сравнение.

## Маршруты Duolingo API

Пути и HTTP-методы запросов перечислены в [`extension/src/duolingoEndpoints.ts`](../../extension/src/duolingoEndpoints.ts).

| Запись                | Назначение                                                                               |
| --------------------- | ---------------------------------------------------------------------------------------- |
| `accountLookup`       | Поиск профиля по `username`. При HTTP 400 запрос с `picture` повторяется без этого поля. |
| `following`           | Список подписок и проверка выбранной подписки перед отпиской.                            |
| `followers`           | Список подписчиков для проверки взаимности.                                              |
| `unfollow`            | Удаление одной подписки по ID аккаунта и ID выбранного профиля.                          |
| `publicProfileLookup` | Диагностический запрос профиля `duo` без использования сессии.                           |

На каждый запрос сравнения или отписки к Duolingo отведено 12 секунд. Сайт ждёт ответ коннектора до 30 секунд при сравнении
и до 45 секунд при отписке.

### Обновление маршрута

1. Обнови путь или версию нужной записи в `duolingoEndpoints.ts`.
2. Выполни `npm --prefix extension run build` и перезагрузи DuoFollow Connector в `chrome://extensions`.
3. Повтори действие на сайте и сверь адрес, статус и ответ запроса во вкладке Network инспектора service worker.

Если меняются параметры запроса или поля ответа, проверь [обработчики](../../extension/src/duolingo.ts)
и [типы ответов](../../extension/src/dto/DuolingoFollowingDto.ts).
При смене домена проверь `host_permissions` в `extension/manifest.json`.

## Запуск локально

Понадобится Node.js 22. Из корня проекта:

```bash
npm ci
npm --prefix extension ci
npm --prefix extension run build
```

В `chrome://extensions` включи режим разработчика и загрузи распакованное расширение из `extension/dist`. Скопируй его
ID в корневой файл `.env.local`:

```dotenv
VITE_DUOFOLLOW_EXTENSION_ID=<ID установленного расширения>
```

Запусти `npm run dev -- --strictPort` и открой `http://localhost:5173/duofollow/`. Войди в Duolingo в том же профиле Chrome
и укажи имя своего аккаунта. Если изменился `.env.local`, перезапусти Vite. После правок расширения пересобери его и
нажми «Перезагрузить» в `chrome://extensions`.

Для проверки сайта из `dist` выполни `npm run build`, останови dev-сервер и запусти `npm run preview -- --port 5173 --strictPort`.
Открой `http://localhost:5173/duofollow/`. Порт 5173 входит в список разрешённых адресов коннектора.

## Проверки перед коммитом

```bash
npm test
npm run format:check
npm run build
npm --prefix extension run build
```

Vitest проверяет полный и неполный Followers, дедупликацию, обработку отказов и тайм-аутов, сохранение аккаунта, окно виртуализации
на 10 000 записях и повторный показ битого аватара. В тестах API используются подставные ответы. Сборка расширения проверяет TypeScript
и помещает манифест, фоновые модули и PNG-иконки в `extension/dist`.

### Ручная проверка перед выпуском

1. Перезагрузи расширение. В `chrome://extensions` должны появиться его иконка и описание.
2. Сравни подписки своего аккаунта. В Network инспектора service worker проверь запросы профиля, Following и Followers.
   Сверь профиль в шапке и счётчик охвата. Обновление страницы должно запустить одно автоматическое сравнение.
3. Проверь поиск без совпадений, ссылку на профиль и выделение имени. Прокрути список вниз и обратно. При проверке сетевых запросов
   за аватарами оставь опцию **Disable cache** выключенной.
4. Открой окно отписки с клавиатуры. Фокус должен быть на «Отмена». Escape закрывает окно и возвращает фокус в карточку.
   После подтверждения проверь ответ Duolingo, исчезновение карточки, счётчики и позицию списка. Повторное сравнение должно
   показать обновлённые данные. При включённом уменьшении движения карточка исчезает сразу.
5. Проверь уведомления об успехе и ошибке, закрытие кнопкой и паузу таймера при наведении и фокусе.

## GitHub Pages

1. В репозитории открой **Settings → Pages → Build and deployment → Source** и выбери **GitHub Actions**.
2. В **Settings → Secrets and variables → Actions → Variables** создай переменную репозитория `VITE_DUOFOLLOW_EXTENSION_ID`
   со значением ID распространяемого Chrome-расширения.
3. Workflow запускается при пуше в `main` или вручную через Actions. Он запускает тесты и проверку форматирования,
   передаёт ID в Vite и публикует папку `dist`. При пустом ID шаг сборки останавливается с сообщением об ошибке.

Файл `.env.local` используется локально. Значение `VITE_*` попадает в клиентскую сборку, поэтому здесь нужен публичный ID расширения.
Для публикации используй стабильный ID одной распространяемой сборки, чтобы посетители сайта могли установить совместимое расширение.
Для другого адреса Pages сверь `base` в `vite.config.ts`, список `externally_connectable.matches` в манифесте,
а также `ALLOWED_ORIGINS` и `UNFOLLOW_PATHS` в service worker. Workflow публикует сайт. Расширение собирается отдельно в `extension/dist`.

- [Vite — переменные окружения](https://vite.dev/guide/env-and-mode)
- [GitHub Actions — переменные репозитория](https://docs.github.com/en/actions/how-tos/write-workflows/choose-what-workflows-do/use-variables)
- [Chrome — стабильный ID расширения](https://developer.chrome.com/docs/extensions/reference/manifest/key)

## План развития

### Аккаунт активной сессии

Шапка показывает профиль результата с подписью «Результат для». Чтобы показывать аккаунт активной сессии независимо от введённого
имени, сначала нужно подтвердить источник профиля на стороне Duolingo. Текущий поиск `users{id,username,picture}` находит профиль
по имени, введённому в форме.

### Поддержка браузеров

| Браузер              | Статус   | Цель                                                                                      |
| -------------------- | -------- | ----------------------------------------------------------------------------------------- |
| Google Chrome (ПК)   | Работает | Основная сборка расширения Manifest V3 и текущая связь с сайтом DuoFollow.                |
| Microsoft Edge (ПК)  | В плане  | Проверить текущую Chromium-сборку в `edge://extensions` и выбрать способ распространения. |
| Mozilla Firefox (ПК) | В плане  | Подготовить сборку WebExtensions и канал связи с интерфейсом для Firefox.                 |

- **Edge.** Проверить установку распакованного расширения, фактический ID, передачу сообщений и запросы Duolingo с сессией Edge.
  Для публикации заранее сверить ID расширения, которое установит пользователь, с ID, используемым сайтом.
  [Документация Microsoft](https://learn.microsoft.com/en-us/microsoft-edge/extensions-chromium/developer-guide/port-chrome-extension)
- **Firefox.** Запускать фоновый код через `background.scripts`. Для сайта на GitHub Pages добавить content script,
  который подключается только на страницах DuoFollow и передаёт проверенные команды фоновому скрипту расширения.
  Прямой вызов `runtime.sendMessage` с веб-страницы через `externally_connectable.matches` в Firefox пока недоступен.
  [Фоновые скрипты Firefox](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/manifest.json/background),
  [статус поддержки прямых сообщений](https://bugzilla.mozilla.org/show_bug.cgi?id=1319168)

Критерий поддержки нового браузера — расширение устанавливается, сайт сравнивает списки в текущей сессии Duolingo, показывает охват,
восстанавливает сохранённый аккаунт и сообщает об ошибках. Для функций записи потребуется также отдельная ручная проверка в каждом поддерживаемом браузере.

### Интернационализация

1. Вынести весь интерфейс, уведомления и подписи доступности в типизированные словари. Из расширения передавать стабильные
   коды ошибок и параметры для перевода.
2. Добавить выбор языка и сохранение настройки. Начать с русского, английского, украинского и испанского. Затем добавить
   французский, немецкий, португальский, итальянский, польский, японский и другие языки по мере проверки переводов.
3. Использовать `Intl.NumberFormat` и `Intl.PluralRules`, обновлять `html[lang]`, предусмотреть поддержку направления текста.
   Проверить полноту ключей, переключение языка, fallback и размещение длинных переводов на узком экране.

# Информация для разработки

Текущий документ описывает вектор развития проекта и его текущее состояние

## Ручная проверка перед выпуском

1. Запусти сравнение для своего аккаунта. В Network инспектора service worker проверь три GET-запроса и соответствие аккаунта на странице.
2. Обнови страницу после успешной проверки. Сохранённый аккаунт должен провериться один раз автоматически. Ввод нового
   имени до отправки формы должен сохранить текущий список.
3. Проверь поиск с нулём совпадений, прокрутку до последней карточки и копирование имени или `@username`. Клик по свободной
   части карточки открывает профиль.
4. Проверь успешное и ошибочное уведомления, ручное и автоматическое закрытие и остановку таймера при наведении и фокусе.

## GitHub Pages

1. В репозитории открой **Settings → Pages → Build and deployment → Source** и выбери **GitHub Actions**.
2. В **Settings → Secrets and variables → Actions → Variables** создай переменную репозитория `VITE_DUOFOLLOW_EXTENSION_ID`
   со значением ID распространяемого Chrome-расширения.
3. Workflow передаст переменную шагу Vite. При её отсутствии сборка завершится с поясняющей ошибкой.

Файл `.env.local` используется локально. Значение `VITE_*` попадает в клиентскую сборку, поэтому здесь нужен публичный ID расширения.
Для публикации используй стабильный ID одной распространяемой сборки, чтобы посетители сайта могли установить совместимое расширение.
Для сборки из другой папки или для другого адреса Pages сверь `base` в `vite.config.ts`, список `externally_connectable.matches`
в манифесте и `ALLOWED_ORIGINS` в service worker.

- [Vite — переменные окружения](https://vite.dev/guide/env-and-mode)
- [GitHub Actions — переменные репозитория](https://docs.github.com/en/actions/how-tos/write-workflows/choose-what-workflows-do/use-variables)
- [Chrome — стабильный ID расширения](https://developer.chrome.com/docs/extensions/reference/manifest/key)

## План развития

### Отписка от одного пользователя

1. Подтвердить текущий запрос штатной кнопки Duolingo в Network на своём аккаунте. Для реализации нужны метод, путь,
   статус и форма данных запроса и ответа. Достаточно обезличенного примера с разделёнными ID аккаунта и цели.
   Заголовки с авторизацией и cookies для этого не нужны.
2. Реализовать команду в расширении с проверкой отправителя, аккаунта и выбранного `userId`. Добавить явное подтверждение одного
   действия из карточки и заблокировать повторное нажатие, пока запрос выполняется.
3. После подтверждённого ответа обновить строку и счётчики или перечитать списки. При ошибке сохранить строку и показать понятное уведомление.
4. Покрыть успешную отписку, отмену, повторный клик, потерю сессии, отказ API и неоднозначный сетевой сбой. Выполнить
   одну ручную проверку на выбранной подписке.

### Интернационализация

1. Вынести весь интерфейс, уведомления и подписи доступности в типизированные словари. Из расширения передавать стабильные
   коды ошибок и параметры для перевода.
2. Добавить выбор языка и сохранение настройки. Начать с русского, английского, украинского и испанского. Затем добавить
   французский, немецкий, португальский, итальянский, польский, японский и другие языки по мере проверки переводов.
3. Использовать `Intl.NumberFormat` и `Intl.PluralRules`, обновлять `html[lang]`, предусмотреть поддержку направления текста.
   Проверить полноту ключей, переключение языка, fallback и размещение длинных переводов на узком экране.

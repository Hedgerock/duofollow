# Руководство разработчика DuoFollow

DuoFollow — неофициальное приложение на React и TypeScript для поиска невзаимных подписок Duolingo.

## Запуск локально

Для локального запуска требуется Node.js 22.13 или новее в ветке 22. Команды выполняются из корня проекта.

```bash
npm ci
npm --prefix extension ci
npm --prefix extension run build
```

Распакованная сборка из `extension/dist` загружается через `chrome://extensions` в Chrome или `edge://extensions` в Microsoft Edge в режиме разработчика.
ID установленного расширения указывается в корневом файле `.env.local`.

```dotenv
VITE_DUOFOLLOW_EXTENSION_ID=<ID расширения Chrome>
# Необязательно, если ID установки Edge отличается:
VITE_DUOFOLLOW_EDGE_EXTENSION_ID=<ID расширения Edge>
```

Команда `npm run dev -- --strictPort` запускает сайт по адресу `http://localhost:5173/duofollow/`.
Для сравнения требуется активная сессия Duolingo в том же профиле браузера и доступ, выданный через настройки Connector.
После проверки аккаунта сравнение начинается автоматически; при сбое доступен ручной ввод. Изменение `.env.local` требует перезапуска Vite. После правок расширения
требуется новая сборка и её перезагрузка через кнопку «Перезагрузить» на странице расширений текущего браузера.

Проверка сайта из `dist` начинается со сборки через `npm run build`. После остановки dev-сервера команда
`npm run preview -- --port 5173 --strictPort` открывает сборку по адресу `http://localhost:5173/duofollow/`.
Порт 5173 входит в список разрешённых адресов Connector.

ID Edge выбирается по сведениям браузера; при пустой переменной Edge используется основной ID.
Переменные входят в клиентскую сборку и не содержат секретов. Установки Chrome и Edge имеют отдельные разрешения и сессии.
[Проверка Microsoft Edge](browser-device-compatibility.md#проверка-microsoft-edge) · [ADR-0012](../decisions/records/0012-microsoft-edge.md)

## Браузерные проверки в Docker

Общий код расширения находится в `extension/src/core`, браузерные операции — в `extension/src/platform`.
Firefox имеет отдельную сборку и канал через content script. Команды установки, web-ext и проверки собраны
в [руководстве Firefox](firefox.md). Переменная с ID магазина для Firefox не требуется.

Chrome и Edge используют `createChromiumPlatform`. Клиент протокола принимает `ConnectorTransport`.
Изменения этих границ проверяются [контрактными тестами](browser-adapter-contracts.md#проверки) и повторным прогоном установленной сборки.

Браузерное окружение Docker собирает зависимости и тестовые сборки заранее.
Параллельность и лимиты описаны в [руководстве проверки ресурсов](release.md#ресурсы-контейнера-и-сравнение-прогонов).
Отчёт одного запуска находится в `test-results/container-resources.json`.

## Настройки интерфейса

Настройка `tooltips` хранится в `duofollow.appearance`; отсутствие значения означает включённый показ.
Явное сохранённое `false` восстанавливает отключение. Атрибут `data-tooltips` общего макета
переключает курсор маркеров статуса между обычным указателем и справкой.
`TooltipProvider` координирует подсказки всего сайта. Проверки поведения описаны в
[руководстве выпуска](release.md#геометрия-сравнения-и-подсказки).

## Линтинг и импорты

Команда `npm run lint` запускает проверки из корня проекта. Команда `npm run lint -- --fix` применяет автоисправления ESLint.
ESLint проверяет JavaScript и TypeScript, правила и зависимости React Hooks, алиасы и порядок импортов.
`npm run format:check` отдельно сверяет форматирование через Prettier.

Алиас `@duofollow/*` задаёт внутренний путь от корня репозитория до файла. Примеры путей —
`@duofollow/src/pages/SettingsPage` и `@duofollow/extension/src/locales`. В импортах модулей расширение файла опускается.
В импортах ресурсов сохраняются расширение и суффикс запроса, например `@duofollow/privacy/index.html?raw`.

Порядок импортов с одной пустой строкой между группами:

1. Встроенные модули Node.js с префиксом `node:`.
2. Сторонние пакеты.
3. Внутренние модули через `@duofollow/*`.
4. Импорты только типов через `import type`.
5. Стили и другие импорты ради побочных эффектов в исходном относительном порядке.

TypeScript и Playwright используют `compilerOptions.paths` из корневого `tsconfig.json`. Vite настраивает тот же алиас
для сайта и Vitest. Connector проверяет типы через TypeScript и собирает `background.js`, `access.js`
и `unfollow-confirmation.js` через esbuild.

## Состояние интерфейса

Подсказки IDE при наведении на `SiteLayout`, `Workspace`, `VirtualFollowingList` и `DuoFollowConnector` описывают назначение
и условия использования компонентов и классов. JSDoc дополняет карту состояния ниже.

- `SiteLayout` держит настройки оформления и рабочее состояние сравнения, пока пользователь переходит между страницами.
  `Outlet` передаёт их текущему маршруту. `localStorage` хранит язык, тему, оформление и имя из успешного ручного сравнения.
- `useWorkspace` связывает состояние Connector, сравнение, отписку и уведомления. Результат сравнения хранится в памяти.
  Фильтр, выбранный вид и сортировка выводят данные из этого результата. При отзыве доступа `useWorkspace` очищает данные
  и отменяет применение поздних ответов через хуки сравнения и отписки.
- Окно виртуализации, фокус, подсказки и открытие аккордеона принадлежат компонентам, которые их отображают.
  Прокрутка меняет окно списка без обновления контекста всего сайта.

Связи компонентов и критерии выделения модулей описаны в [архитектуре DuoFollow](architecture.md).

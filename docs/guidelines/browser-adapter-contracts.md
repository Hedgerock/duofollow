# Контракты платформы и транспорта

## Состав

[`ExtensionPlatform`](../../extension/src/platform/ExtensionPlatform.ts) описывает возможности среды расширения.
[`createChromiumPlatform`](../../extension/src/platform/chromium.ts) связывает их с Chrome SDK и используется также в Edge.
[`background.ts`](../../extension/src/background.ts) запускает
[`startConnector`](../../extension/src/core/createConnector.ts) с этим адаптером.

| Модуль core         | Ответственность                                              | Внешние зависимости                                     |
| ------------------- | ------------------------------------------------------------ | ------------------------------------------------------- |
| `createConnector`   | Допуск команд, согласие, события и отмена при отзыве доступа | Платформа и фабрики сценариев                           |
| `duolingoSession`   | ID сессии, кеш и проверка профиля                            | Чтение cookie, общая пауза, HTTP-ответы                 |
| `duolingoRateLimit` | Самый поздний срок после HTTP 429                            | Session storage                                         |
| `duolingo`          | Сравнение и проверенная отписка                              | Сессия, HTTP, общая пауза                               |
| `unfollowRequests`  | Одноразовое подтверждение, журнал и восстановление           | Сетевой сценарий, доступ, хранилище, окно подтверждения |

Создание фабрики не читает browser SDK. Рабочие состояние и кеши относятся к экземпляру core.
`local` хранит версии согласия и язык, `session` — общую паузу и журнал операции.
Адаптер сохраняет эти области и их ошибки; отказ хранилища не превращается в согласие или разрешение на запись.
Запрос разрешения вызывается непосредственно из обработчика действия пользователя.

## Источник команды

Тело сообщения считается непроверенным. URL, frame ID, extension ID, tab и document ID берутся из метаданных,
предоставленных браузером адаптеру; в Firefox ID документа дополняется закрытым токеном content script. Core проверяет эти сведения перед выполнением команды.
Поле `sender` или `documentId` внутри сообщения не заменяет метаданные отправителя.
Сравнение и отписка доступны на главной, открытие настроек — также на странице управления доступом.
Подтверждение стандартной отписки принимается только от собственной страницы расширения в верхнем фрейме.

Объект платформы является доверенной зависимостью точки входа, а не данными из веб-страницы.
Firefox-адаптер сохраняет эти свойства при доставке через content script.
ID документа создаётся в изолированном окружении и передаётся только через проверенный нативный порт.
Подробности находятся в [руководстве Firefox](firefox.md).
Если браузерный API не предоставляет подходящий document ID, адаптеру требуется отдельная проверенная
привязка к документу. Одного URL или ID вкладки для такой привязки недостаточно.

## Транспорт сайта

[`ConnectorTransport`](../../src/api/extension/ConnectorTransport.ts) содержит `request` и `watch`.
`request` возвращает непроверенный ответ и принимает сигнал отмены ожидания. `watch` возвращает
идемпотентную функцию прекращения подписки; после неё сообщения не доставляются.
Удалённое закрытие канала уведомляет подписчика один раз.

[`chromiumTransport`](../../src/api/extension/chromiumTransport.ts) использует Runtime-сообщения и внешний порт.
[`DuoFollowConnector`](../../src/api/extension/DuoFollowConnector.ts) проверяет ответы после доставки,
владеет тайм-аутами и продолжает проверку исхода отписки по тому же request ID при потере ответа.
Транспорт не подтверждает удаление самостоятельно и не обходит проверку целевого профиля.
AbortSignal не отзывает уже отправленную Runtime-команду.

## Проверки

`extensionPlatform.contract.test.ts` выполняет девять сценариев для прямой платформы в памяти
и для настоящих Chromium- и Firefox-адаптеров поверх подставного SDK. Во время проверок глобальные SDK отсутствуют.
Набор проверяет происхождение команды, отказ доступа, сравнение, привязку к документу, одноразовую запись,
собственную страницу подтверждения, отзыв согласия, восстановление журнала и общей паузы, изоляцию экземпляров.

`ConnectorTransport.contract.test.ts` проверяет замену транспорта, валидацию ответов, тайм-аут,
прекращение подписки, удалённое закрытие и поздний ответ после отмены.
`browserBoundaries.test.ts` проверяет дерево исходников и зависимости core.
Существующие `background.test.ts` и `access.test.ts` продолжают проверять Chromium-вход и страницы расширения.

```sh
npm test
npm --prefix extension run build
npm run test:browser:docker
npm run test:edge
```

После обновления `extension/dist` установленная распакованная сборка перезагружается.
Ручная проверка охватывает согласие, активный аккаунт, сравнение, стандартную и быструю отписку,
отзыв доступа и открытие настроек рядом с вкладкой сайта в Chrome, Edge и Firefox.
[Проверки Firefox](firefox.md) включают отдельный сценарий установленной тестовой сборки.

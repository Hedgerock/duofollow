# Локальная проверка параллельности браузерных тестов

## Окружение и область

Дата: 22 ноября 2026 года. Базовый коммит — `8c4252f`.
Состояние проекта включает [ADR-0013](../decisions/records/0013-workspace-scroll-and-tooltips.md)
и [ADR-0014](../decisions/records/0014-tooltip-preferences-and-lifecycle.md).
Изменение тестового окружения описано в [ADR-0015](../decisions/records/0015-browser-test-container-resources.md).

Окружение: Windows `10.0.26200`, Node.js `22.18.0`, Playwright `1.57.0`,
Chromium `143.0.7499.4`. Доступны 16 логических CPU и около 32 ГиБ памяти.
Контейнерные лимиты CPU и памяти в этом прогоне не применялись.

Проверены 57 интеграционных сценариев, включая нативный select, настройки подсказок,
смену курсора и установленный тестовый Connector с подставными ответами Duolingo.
Сайт и расширение собраны заранее. Страницы сайта выдаются из каталога `dist` через маршрутизацию Playwright,
поскольку окружение ограничивает обращения к локальному HTTP-серверу.
Linux-скриншоты и нагрузочный сценарий в сравнение времени не входили.

## Результат

Перед сравнением прошёл прогревочный запуск с двумя воркерами: 57 сценариев завершились успешно.
Затем один и тот же актуальный набор последовательно выполнен с одним и двумя воркерами.

| Воркеры | Успешные сценарии | Время процесса Playwright с запуском |
| ------- | ----------------- | ------------------------------------ |
| 1       | 57                | 58,702 с                             |
| 2       | 57                | 33,890 с                             |

Это предварительный парный замер Windows/Chromium. Он показывает возможность ускорения данного набора,
а подтверждение в целевом Docker требует собственного прогона. Показатели предыдущего набора из 48 сценариев
не используются для оценки текущего состояния.

## Конфигурация и локальные проверки

274 unit-теста завершились успешно. Проверены сборки сайта и расширения.
Клиентская команда `docker compose config` подтвердила два воркера, лимит 4 CPU и 3 ГиБ,
а также переопределение на один воркер, 2 CPU и 2 ГиБ.

Счётчики cgroup в локальном Windows-прогоне отсутствуют, поэтому его отчёт сохранил `null` для пика и лимита памяти.
Docker Engine в окружении этого локального замера был недоступен. Результат отдельного контейнерного запуска приведён ниже.

## Подтверждённый Docker-прогон

После применения изменения в рабочем каталоге проекта проверены отчёты от 22 ноября 2026 года, 17:15 по Киеву.
Файл `test-results/container-resources.json` новее изменённых исходников и содержит пустой список аргументов,
код завершения `0` и отсутствие сигнала завершения. Файл `test-results/.last-run.json` содержит статус `passed`
и пустой список упавших тестов. Проверка модели Compose подтвердила настройки по умолчанию:
два воркера, 4 CPU и 3 ГиБ памяти; визуальный проект ограничен одним воркером.

| Показатель                       | Значение                           |
| -------------------------------- | ---------------------------------- |
| Длительность процесса Playwright | 43,765 с                           |
| Пик памяти cgroup                | 1 750 626 304 байт, около 1,63 ГиБ |
| Лимит памяти                     | 3 221 225 472 байт, 3 ГиБ          |
| Доля лимита на пике              | около 54,3 %                       |

Запуск завершился успешно при заданном лимите памяти. Один сохранённый отчёт не доказывает снижение расхода памяти
по сравнению с прежним окружением и не позволяет сравнить холодный и повторный запуск на кэше.
Ранее наблюдавшиеся 490,7 МБ отражали текущий расход, поэтому с пиком этого прогона напрямую не сравниваются.
Время Windows-прогона из 57 интеграционных сценариев не сопоставляется напрямую с контейнерным запуском
интеграционных и визуальных проверок.

Для сравнительного замера отчёты `test-results/container-resources.json` сохраняются отдельно для каждого прогона.
Лимиты Compose и отчёт относятся к тестовому контейнеру; сборка образа и общая память Docker Desktop измеряются отдельно.

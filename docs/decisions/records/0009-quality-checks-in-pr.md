# ADR-0009: Проверки кода в pull request

## Статус

Accepted

---

## Контекст

Pull request запускает интеграционные и скриншотные тесты Chromium. Vitest, ESLint и Prettier входят
в workflow публикации GitHub Pages, который запускается после push в `main`. Ошибка модульного теста,
нарушение правил линтера или сбой проверки форматирования могут обнаружиться уже после слияния.

---

## Решение

Workflow Quality checks запускает Vitest, ESLint и Prettier на pull request. Он использует Node.js 22,
устанавливает зависимости по `package-lock.json` и работает с правом чтения содержимого репозитория.
Устаревший запуск для того же ref отменяется после появления нового.

Workflow Browser tests выполняется параллельно. Workflow публикации сохраняет проверки перед выкладкой
для изменений, попадающих в `main` прямым push.

---

## Последствия

Результаты проверок кода и браузерных сценариев видны отдельно в GitHub Checks. Для модульных тестов,
линтинга и проверки формата достаточно Node.js. Docker по-прежнему нужен браузерному workflow.

---

## Границы решения

Решение охватывает запуск проверок в CI. Обязательность статусов при слиянии задаётся правилами ветки.
Нагрузочный тест запускается отдельно.

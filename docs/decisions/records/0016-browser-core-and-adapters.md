# ADR-0016: Общая логика и браузерные адаптеры

## Статус

Accepted

---

## Контекст

Chrome и Edge используют одну сборку Manifest V3. Проверка сессии, пауза после HTTP 429,
журнал отписки и worker обращались к `chrome.*` из сценариев. Клиент сайта совмещал правила протокола
и доставку через Runtime. Подключение Firefox требует другого фонового окружения и транспорта сообщений.
Существующие ограничения источника команды, согласия и подтверждения записи остаются обязательными.

---

## Решение

Каталог `extension/src/core` содержит фабрики проверки сессии, сетевых операций, общей паузы,
подтверждения отписки и запуска обработчиков команд. Каждая фабрика получает необходимые зависимости.
Кеш сессии, срок паузы, подтверждение и восстановление принадлежат экземпляру core, а не модулю.
Чистые DTO, валидаторы, маршруты, разбор ответов и правила согласия используются совместно.

Контракт `ExtensionPlatform` задаёт чтение cookie, local/session storage, разрешения, размещение настроек,
окно подтверждения и события. Метаданные отправителя поступают от адаптера отдельно от тела команды.
`platform/chromium.ts` реализует контракт для Chrome и Edge. Входной `background.ts` выбирает адаптер
и запускает один core на время жизни worker. Страницы расширения используют этот же адаптер для SDK-операций.

Core сохраняет проверку origin, маршрута, верхнего фрейма и страницы подтверждения. Запрос отписки и его статус
привязаны к идентификатору документа. Недоступный идентификатор не заменяется значением из тела сообщения.
Согласие и сессия повторно проверяются перед записью. Журнал служит для чтения результата после перезапуска,
а подтверждённая операция не отправляется повторно.

`DuoFollowConnector` получает `ConnectorTransport`. Конструктор со строковым ID сохраняет существующий API
и выбирает Chromium-транспорт. Конструктор с объектом транспорта позволяет заменить доставку команд и событий.
Проверки ответов, статусов, целевого ID и восстановление отписки остаются в клиенте протокола.
Тайм-аут передаёт транспорту AbortSignal. Chromium-транспорт освобождает обработчик отмены и читает `lastError`
даже из позднего ответа. Отмена ожидания не отменяет уже отправленную браузеру команду или запись на стороне Duolingo.

Один контрактный набор выполняется против платформы в памяти и Chromium-адаптера поверх подставного SDK.
Архитектурные тесты запрещают обращения к SDK вне адаптера расширения и в клиенте протокола,
а также зависимости core от браузерных реализаций и точек входа.

---

## Последствия

Общая логика проверяется без глобального браузерного SDK. Новый адаптер получает существующие сценарии
и контрактные проверки. Chrome и Edge сохраняют одну реализацию адаптера и прежний протокол.
Структура добавляет явные зависимости между фабриками, но не вводит отдельный пакет, контейнер зависимостей
или библиотеку управления состоянием. Ключи хранилища и версии согласия сохраняются.

---

## Границы решения

Firefox-сборка, content script и bridge сообщений входят в следующую итерацию.
Такой bridge должен получать проверенные метаданные отправителя и обеспечивать привязку к конкретному документу.
Поддержка Firefox не считается реализованной после выделения core.
Safari, разделение стилей и новое оформление остаются отдельными задачами.
Контрактные тесты с подставным SDK дополняются проверкой установленного расширения и реальной сессии
в каждом поддерживаемом браузере.

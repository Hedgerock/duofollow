# ADR-0015: Ресурсы и параллельность браузерных тестов

## Статус

Accepted

---

## Контекст

Каждый запуск Compose выполнял `npm ci` в общем томе зависимостей. Подготовка повторялась при неизменном lockfile.
Исходники и зависимости монтировались в контейнер. Сборка расширения в `beforeAll` могла выполняться одновременно
с браузерными тестами. Переменная `CI=true` ограничивала весь прогон одним воркером.
На контрольном сообщении Docker были доступны 16 CPU и около 15 ГБ памяти, но максимальное потребление памяти не измерялось.

---

## Решение

`Dockerfile.test` использует прежний образ Playwright 1.57.0 Noble. Зависимости устанавливаются отдельным слоем
по `package.json` и `package-lock.json`. Исходники копируются после установки. Сайт и расширение собираются до запуска браузеров.
Команды npm вызывают `docker compose run --build`, поэтому изменение исходников проверяет свежую сборку,
а неизменные слои могут использоваться повторно.

Во время тестов монтируются результаты и эталонные скриншоты. Зависимости и сборки берутся из образа.
Флаг `DUOFOLLOW_TEST_PREBUILT=1` включает preview готового сайта и исключает повторную сборку расширения в тесте.
Обычный запуск вне образа сохраняет подготовку сборок.

Контейнер по умолчанию использует два воркера, лимит 4 CPU и 3 ГиБ памяти.
Значения меняются через `DUOFOLLOW_TEST_WORKERS`, `DUOFOLLOW_TEST_CPUS` и `DUOFOLLOW_TEST_MEMORY_LIMIT`.
Параметр Playwright `--workers` позволяет изменить параллельность отдельного запуска.
Интеграционные случаи независимы и выполняются параллельно внутри файлов.
Файл установленного Connector сохраняет последовательное выполнение.
Проект визуальных тестов ограничен одним воркером, нагрузочный конфиг сохраняет один воркер.
Вне Compose обычный локальный предел — два, CI без явного значения — один.

`scripts/run-browser-tests.mjs` передаёт параметры Playwright, сохраняет ненулевой код завершения
и записывает длительность и пик памяти cgroup в `test-results/container-resources.json`.
При отсутствии поддерживаемых счётчиков значение памяти равно `null`.
CI сохраняет отчёт отдельным артефактом.

---

## Последствия

Повторный локальный запуск использует кэш установки и сборок. Компиляция не конкурирует с браузерами во время тестов.
Два воркера могут ускорить независимые сценарии за счёт большего расхода памяти, чем один воркер.
Отчёт позволяет сравнить одинаковые наборы с разной параллельностью.
Изменение lockfile, версии образа или очистка кэша требует повторной подготовки.
На одноразовом CI-окружении кэш между заданиями без отдельного хранилища не гарантирован.

---

## Границы решения

Лимиты Compose относятся к запущенному тестовому контейнеру. Они не ограничивают весь Docker Desktop,
виртуальную машину WSL и фазу сборки образа. Отчёт охватывает выполнение Playwright и его дочерние процессы.
Принудительно завершённый контейнер может не оставить отчёт.
Снижение пика памяти и ускорение подтверждаются измерениями холодного и повторного запуска в целевом Docker.
Изменение не задаёт новый лимит памяти для самого приложения.

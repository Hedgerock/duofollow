# ADR-0010: Валидация ответов Duolingo и Connector

## Статус

Accepted

---

## Контекст

Connector проверяет форму ответов Duolingo, а сайт проверяет поля сравнения перед выводом. Некоторые неверные
идентификаторы проходят первую проверку. Счётчики, статусы и списки могут иметь допустимые типы и при этом
противоречить друг другу. Успешный ответ сравнения содержит поля, оставшиеся от исследования пагинации.

---

## Решение

Connector разбирает ответы API из `unknown`. Профиль и страницы Following и Followers должны содержать
положительные безопасные целые ID. Страницы также требуют список, неотрицательный целый итог и допустимый курсор.
Повторяющиеся ID страниц объединяются при сравнении. Необязательные поля отображения по-прежнему допускают подстановку.

Клиент сравнивает счётчики с охватом и полученными списками. Он проверяет уникальность ID в списках,
число взаимных профилей и согласованность списка невзаимных с общим списком при его наличии.
Согласованные ответы старого формата без `coverage` или списка `following` поддерживаются.
Расхождение с итогом Duolingo сохраняется как частичный охват при `total-mismatch`.

Успешный ответ `GET_FOLLOWING_SUMMARY` содержит `success` и `comparison`. Клиент принимает прежние ответы
с исследовательскими полями и использует только рабочую часть результата.

---

## Последствия

Несогласованный результат возвращает `INVALID_RESPONSE`. Сайт сохраняет предыдущий результат, если к моменту
ошибки он ещё доступен. При неверной странице Following на этапе подтверждения отписки запрос `DELETE`
не отправляется. Проверка сессии использует тот же парсер Followers.

---

## Границы решения

Запросы получают первую страницу списков. Проверка структуры ответа на отписку сохраняет отдельную обработку
неподтверждённого результата и его восстановление.

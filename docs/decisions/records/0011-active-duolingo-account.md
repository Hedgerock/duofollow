# ADR-0011: Автоматическое подключение аккаунта Duolingo

## Статус

Accepted

---

## Контекст

Connector узнаёт ID активной сессии Duolingo из сессионного cookie.
Для сравнения сайт запрашивал имя этого же аккаунта вручную, а расширение сверяло найденный профиль с сессией.
Пользователь мог ввести имя другого аккаунта и получить отказ, хотя вход в браузере уже выполнен.

---

## Решение

После выдачи доступа Connector проверяет сессию запросом Followers с `pageSize=1`.
По подтверждённому ID расширение получает имя и аватар через `/2017-06-30/users/{id}?fields=id,username,picture`.
Ответ принимается при совпадении ID профиля с ID сессии. Перед передачей профиля сайту Connector снова сверяет ID сессии.

Сайт показывает карточку подключённого аккаунта и запускает одно сравнение. Переключение маршрутов, повторная
проверка сессии и обновление аватара сохраняют текущий результат. Кнопка «Обновить сравнение» повторяет сравнение
для того же аккаунта. При смене ID, выходе из уже подтверждённой сессии или отзыве доступа результаты сбрасываются.
Поздние ответы прежней операции игнорируются.

При сбое поиска профиля доступна повторная проверка и ручной ввод имени. Старый Connector продолжает работать
через форму. Имя сохраняется в браузере после успешного сравнения через форму.

---

## Последствия

В обычном сценарии сравнение начинается после предоставления доступа и проверки сеанса. Идентификатор, имя
и разрешённый адрес аватара передаются сайту для сравнения и отображения. Успешный профиль кешируется на 60 секунд
в памяти worker и используется для сравнения. Значение cookie обрабатывается в расширении. Новые разрешения не требуются.

---

## Границы решения

Профиль читается через внутренний маршрут Duolingo. Доступность маршрута требуется проверить
в браузере с установленным расширением и активной сессией. Автоматический сценарий покрыт тестами с подставными ответами.
Ссылка на профиль в шапке по-прежнему относится к результату сравнения.

# ADR-0017: Сборка Firefox и канал через content script

## Статус

Accepted

---

## Контекст

После ADR-0016 core получает браузерные возможности через ExtensionPlatform. Firefox использует фоновую
страницу Manifest V3 вместо service worker Chromium. Прямая связь веб-страницы через
externally_connectable.matches не обеспечивает канал Firefox. Поддержка версий до Firefox 153 не позволяет
опираться на runtime.MessageSender.documentId. Отписка требует сохранения привязки к документу.

---

## Решение

Сборка Firefox выпускается отдельно в extension/dist-firefox. Manifest задаёт background.scripts,
content script на страницах DuoFollow, фиксированный Gecko ID и минимальную версию Firefox Desktop 140.
Минимальная версия Gecko Android 142 отражает совместимость декларации данных; поддержка Android этим
решением не объявляется. Архив публикации исключает локальные origin. Chrome и Edge сохраняют свою сборку.

platform/firefox.ts реализует ExtensionPlatform через нативный browser API. Точки входа выбирают адаптер
на этапе сборки. Страницы доступа и подтверждения используют тот же интерфейс платформы, локализацию
и ключи согласия. Настройки открываются рядом с инициирующей вкладкой; её положение повторно читается
перед открытием, поскольку порт может пережить перенос вкладки в другое окно.

Сайт выбирает Firefox-транспорт по браузеру, без переменной с ID магазина. Content script работает
в изолированном окружении верхнего фрейма. Window-сообщения проверяются по source, origin, каналу,
направлению и идентификаторам. В фоновый скрипт передаются только команды публичного протокола.
Внутренние команды стандартного подтверждения через этот канал недоступны.

Нативный порт принимается только от собственного расширения, верхнего фрейма и разрешённой страницы.
Для локальной разработки принимается порт 5173. Текущий URL читается content script, а не из тела команды сайта.
После проверки origin и префикса маршрута core дополнительно проверяет точный маршрут для каждой команды.
Перейти с публичной страницы на главную можно без повторной загрузки content script.

Content script создаёт случайный идентификатор документа один раз в изолированном окружении.
Он передаётся только через нативный порт и связывается с ID вкладки из браузерных метаданных.
Сайт не получает и не выбирает этот идентификатор. Переподключение порта сохраняет документ,
перезагрузка создаёт другой идентификатор. Поля sender и documentId из команды сайта не заменяют метаданные.

Запросы и события имеют отдельные типы сообщений. Очередь ограничена 64 запросами и восемью подписчиками.
Отмена освобождает ожидание и обработчики; уже отправленная операция не воспроизводится автоматически.
Закрытие порта завершает ожидания и удаляет подписку core. Поздний ответ старого порта игнорируется.
Восстановление исхода отписки использует существующий журнал и повторно не отправляет DELETE.

web-ext закреплён как инструмент разработки и проверки. Manifest явно декларирует обработку аутентификации,
идентифицирующих данных, содержимого и действий на сайте для работы с Duolingo; декларация none не применяется.
Это не добавляет телеметрию или сервер DuoFollow. Подготовка публикации требует сверки деклараций и политики
с фактическими потоками данных и актуальными правилами AMO.

---

## Последствия

Общий набор сценариев core выполняется также через Firefox-адаптер. Дополнительные тесты проверяют
допуск портов, изоляцию документов, отмену, ограничение очередей и очистку подписок.
Интеграционный сценарий использует реальные Window-сообщения и код bridge с подставным SDK.
Отдельные команды проверяют интерфейс Firefox и временно установленное расширение с тестовыми ответами Duolingo.
Задание Firefox в CI выполняет lint, установленное расширение и интерфейс последовательно.

Новый канал добавляет две границы сообщений. Проверки после доставки остаются в DuoFollowConnector,
а согласие, сессия, одноразовое подтверждение и пауза HTTP 429 остаются в core.

---

## Границы решения

Наличие адаптера, успешный lint и тесты с подставным SDK не подтверждают реальную сессию Firefox.
Приёмка включает установленный Firefox Stable или ESR, выдачу и отзыв доступа, смену аккаунта,
стандартную и быструю отписку, перенос вкладки и проверку вёрстки. Результат фиксирует версию и ОС.
Публикация в AMO, подпись, Safari, контейнерные профили Firefox и Android остаются отдельными вопросами.
